# Verify setup

為這個專案產生技能 `.claude/skills/verify-<app>/`，讓代理能像使用者一樣操作 app 並取得證據。讀者是下一個代理：它沒見過這個 app，會在工作中途直接讀。

## 1. 從專案找答案

只問使用者你觀察不到的事。

- **介面：** 使用者實際接觸的是什麼。網頁、指令工具、桌面 app、API、函式庫。有多種時挑主要的，其餘記下。
- **啟動：** 本機怎麼啟動。優先用專案自己記載的指令。記下連接埠、環境變數、初始資料。
- **操作：** 怎麼用程式操作它。先找現成的：瀏覽器測試、可呼叫的端點、除錯連接埠。沒有才用通用做法：網頁用瀏覽器工具，指令工具用終端機，服務用 HTTP。
- **觀察：** 能取得哪些證據。截圖、終端機輸出、回應內容、紀錄檔、結束碼、資料狀態。
- **隔離：** 能不能同時跑兩份。不能就在產出的技能裡寫明，避免弄壞使用者正在用的那一份。

專案無法建置或啟動時，先修好或精確回報，再產生技能。

## 2. 產生技能

寫出 `.claude/skills/verify-<app>/SKILL.md`，含 frontmatter（`name: verify-<app>`，以及指明 app、介面、使用時機的 `description`；不加 `disable-model-invocation`）與下列各節。內容以實際找到的為準，不留佔位符。

- **啟動：** 確切指令，以及如何判斷已就緒。要能從空的資料狀態到達可用狀態。
- **檢查：** 一個唯讀檢查，確認這個實例值得操作：程式在跑、版本正確、連接埠是自己的。
- **操作：** 這個專案真實的選擇器與指令。優先用穩定的把手：按鈕名稱、路徑、提示文字。不用座標。
- **證據：** 擷取什麼、放在哪。走真實的使用者路徑，不用內部捷徑。擷取動作與動作後的狀態。除了看得見的結果，也驗證副作用：寫入的檔案、新增的資料。
- **清理：** 如何關閉這次啟動的實例。只關自己啟動的。證據保留。

附帶的腳本要能直接執行，並在技能裡示範用法。`SKILL.md` 要指向第 3 步的 `features/README.md`。

## 3. 建立功能地圖

建立 `.claude/skills/verify-<app>/features/`，為最重要的 3 到 5 個功能各寫一個檔案，另加一個 `README.md` 索引。每個檔案從使用者的角度寫四節：

- **子功能**
- **怎麼到達**
- **怎麼操作：** 每一步的指令，以及什麼結果代表正常。
- **注意事項**

缺少前置資料而走不通時，回報失敗，把原因寫進「注意事項」。不為了通過而放寬驗證。

## 4. 實際跑一遍

照產出的技能完整執行：啟動、檢查、操作一個功能、擷取證據、清理。清理後確認證據還在。失敗就修，每次失敗後也要清理。沒有實際跑過的技能只是草稿，不交付。

## 5. 之後

專案有重大改動時重跑本技能，更新功能地圖。
