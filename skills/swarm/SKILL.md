# Swarm

啟動任何子代理前，把四個階段（界定、分派、彙整、回報）抄進任務清單，每完成一個就更新。

## 1. 界定

1. **完成條件。** 寫明完成條件，以及 swarm 要交出的成果或報告。
2. **形態。** 選一種：切成多個分片各派一個工作者；多個工作者拿完全相同的交辦競賽；或兩者混合。競賽或混合形態，啟動前宣告選擇規則：`first pass`（第一個通過的）、`rank all`（全部排名）或 `best-of`（取最好的）。
3. **模型。** 依入口檔的「模型」一節，依工作性質選角色：實作或探索用 `build`，機械式修改與驗證用 `routine`，比較不同模型的競賽用 `panel`。比較不同模型的競賽，事先寫明每一組用哪個模型。某個模型被拒絕，就換一個可用的，並在回報說明。
4. **輸出位置與版本。** 工作者會寫入時，給每個工作者各自的輸出位置。工作者要驗證或量測某個 commit 時，每份交辦寫明確切的 commit SHA。量測的交辦還要寫明方法：樣本數、一個樣本是什麼、執行順序。要求工作者在結果裡記下這兩者。

## 2. 分派

1. **同時啟動。** 在同一則訊息裡啟動全部工作者，`subagent_type: "general-purpose"`。工作者會改檔案時才用 `isolation: "worktree"`，唯讀的不用。
2. **交辦能獨立成立。** 寫明目標、範圍、確切的分片或競賽組別、要 checkout 的 branch 或 commit、怎麼驗證、要回報什麼。
3. **回報格式。** 工作者回報 `PASS`、`ISSUES` 或 `BLOCKED`，並附證據。回報 `ISSUES` 時，列出每一個能證明的問題，不只第一個。
4. **退出。** 某個工作者沒有產出，就用剩下的繼續，並記下這次退出。

## 3. 彙整

1. **檢查方法與版本。** 結果沒有記下交辦裡寫明的 commit SHA 與方法，就捨棄，重派那個工作者一次。第二次還是沒有，記為缺口。缺口不算通過。
2. **覆蓋。** 分片形態下，每個必要的分片都要有結果。
3. **競賽。** 套用事先宣告的選擇規則。
4. **不貼原始輸出。** 只寫彙整後的結論與證據指標。
5. **收尾。** 結束後移除 worktree。要保留的成果先併回目前的 branch。

## 4. 回報

結果表、每個問題一行的摘要、缺口與退出、有競賽時用的選擇規則。
