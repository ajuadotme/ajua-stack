# Recall

開始或恢復工作之前，重建近期的工作脈絡，交回精簡的摘要：事情現在的狀況，以及下一步要做什麼。緊扣主題，只讀範圍內的主題線需要的東西，然後停止。

脈絡存在兩處。對話紀錄記著你做了什麼、決定了什麼。版本紀錄記著同一份程式碼周圍的其餘事情：被 revert 的修正、反覆修同一處的 commit、尚未併回的 branch。有一長串 bug 尾巴的功能，大部分故事在版本紀錄裡，不要只靠對話紀錄。

對話紀錄放在 `~/.claude/projects/<slug>/<session>.jsonl`。`<slug>` 是工作區路徑把每個非英數字元換成 `-` 的結果（`/Users/you/proj` 變成 `-Users-you-proj`）。直接放在該資料夾的最新 `.jsonl` 是目前的對話。每個 `<session>/subagents/` 放該對話的子代理紀錄。每一行是一則訊息。

1. **先分類。** 要接續某一個特定的先前對話，用 `${CLAUDE_PLUGIN_ROOT}/skills/ajua-mode/playbooks/pickup.md`，不是本技能。把習慣轉成持久技能，用 `/ajua-stack:automate-me`。給人看的工作摘要是另一項任務。使用者已給完整的狀態摘要（路徑、branch、改動）時，直接用，跳過挖掘。
2. **先鎖定範圍。** 固定時間窗（「近期」是真實區間，預設最近 7 天）、有指名時固定主題，以及工作區。只讀目前這個工作區的資料夾，不要對 `~/.claude/projects/*/` 做 glob，沒被要求時絕不讀其他專案的紀錄。把範圍複述一遍。絕不默默把「全部」變成「最近 N 個」。
3. **派子代理讀對話紀錄。** 每個子代理負責語料的一個切片，模型依入口檔的「模型」一節，用 `routine` 角色。交辦寫明：依檔案修改時間排序候選，不依 UUID 名稱；先 grep 主題，只讀符合的對話中相關的區段；略過目前的對話與明顯的雜訊（子代理、評測與測試對話）。每個子代理對每個對話回傳一個區塊：主題、使用者的目標、決策、未結的主題線、卡關與修正、產出物（commit、branch、檔案），每項引用對話的 UUID。只有一兩個對話時，略過分派，直接搜尋。原始紀錄留在子代理裡，主線只拿發現。
4. **主題指名了功能、檔案、子系統或 bug 時，掃過版本紀錄。** 這是預設，不是判斷題。用 `git log`、`git log --grep`、被 revert 的 commit 找出：目前狀態、試過但沒有撐住的修法、反覆出現的問題。沒有結果也是發現。只有純粹回想活動、沒指名目標時（「我這週做了什麼」）才略過。
5. **對照即時狀態驗證。** 挖掘浮現的 branch、commit 與改動，用 `git` 確認現況。答案取決於某個代理實際做了什麼（執行的工具、讀的檔案、遇到的錯誤）時，讀完整的對話紀錄，不要只讀修剪過的副本。
6. **依下面的契約寫簡報。** 按主題線分組。

## 簡報契約

順序：摘要、主題線、問題、下一步。更深的細節放下面，或刪掉。

- **摘要。** 最多 5 個條列：這份工作是什麼，整體進展到哪裡。
- **主題線。** 每條一行，前面加恰好一個狀態標籤：`[committed <hash>]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted <hash>]`、`[planned, not started]`。沒有標籤的主題線視為未完成，所以一定要加。
- **問題。** 最多 5 個，挑反覆出現的。寫進被 revert 的修正與反覆出現的症狀，讓下一次嘗試從上一次失敗的地方開始。
- **下一步。** 單一一個最有用的具體動作。

相鄰的功能不納入，除非它擋住這一個。摘要與主題線超過一個畫面時，先刪細節，再刪主題線。對話中的發現引用 UUID，版本紀錄中的發現引用 commit hash。內容若會被放到使用者以外的地方，先清除私人脈絡。

**回報：** 依契約寫成的簡報。
