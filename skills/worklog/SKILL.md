# Worklog

一項工作只維護一份紀錄。其他技能需要決策紀錄時引用本技能，不另訂格式。

## 格式

一個 TSV 檔，第一列是標題列，之後每個決定一列。儲存格只寫一行。證據寫指標，不寫段落。

- `ts`：ISO8601 UTC 時間，例如 `2026-05-24T09:02:00Z`。
- `phase`：階段或工作項目。
- `decision`：選了什麼或做了什麼，一行。
- `why`：理由，用白話。由某條原則促成就直接說出內容，不貼標籤。
- `evidence`：能證明它的指標：commit SHA、`file:line`、成品、紀錄檔或截圖的路徑。不寫敘述。
- `result`：結果或狀態，例如 `tests green`、`reverted`、`pixel-diff 0`、`INCONCLUSIVE`、`open`。

```
ts	phase	decision	why	evidence	result
2026-05-24T09:40:00Z	harness	改任何東西前先替舊版截圖	之後拿新舊版比對，抓出畫面變化	scripts/snapshot.sh, baseline/	存了 120 張參考截圖
2026-05-24T12:30:00Z	widget	丟掉某個子代理的成果，因為它的截圖是空白的	檢查了實際檔案，沒有相信它的摘要	worktree reset	已還原，下次交辦寫得更嚴
```

## 記一列

1. **寫法。** 像跟同事說你做了什麼：具體的動作，白話，不用抽象術語或套話。
2. **附加。** 自己把一列附加到檔尾，只用附加（`>>`），不覆寫檔案。檔案不存在或是空的，先寫標題列。每個儲存格的 tab 與換行換成空格。儲存格以 `=`、`+`、`-`、`@` 開頭時，前面加一個單引號，避免在試算表裡被當成公式。
3. **記什麼。** 記決策點與檢查點，不記每個動作：選定的分岔、完成的單元與它的驗證結果、轉向或還原與其原因、出現的阻礙、設下的關卡。反覆迭代的工作每輪一列。瑣碎與不言自明的事不記。
4. **只增不改。** 決定錯了，新增一列取代它。不編輯、不刪除舊列。
5. **證據優先用腳本。** 優先用已 commit 的腳本產生的證據，不用手工做的一次性證據。

## 執行與 `start` 列

一次執行是一段代理對話，包含之後的回合與對它的摘要。接手的代理、替換的代理或新的對話，算新的一次執行。

- 一次執行要寫入一份已有內容的紀錄檔時，它的第一列 `phase` 寫 `start`。另一次執行的 `start` 列之後，你寫的第一列也是 `start`。
- 在之後的回合回到某份紀錄時，先讀最後幾列，確認期間有沒有別的執行寫入。
- `start` 列寫明在它之前、不是這次執行寫的那些列的 `ts` 範圍；`evidence` 寫明這次執行，例如代理 id。`start` 不用在其他地方。

## 放在哪裡

紀錄預設留在本機，不 commit。放在工作目錄的 `decisions.tsv`；多個任務共用同一個資料夾時，用 `.audit/<task-slug>.tsv`。讓它不進 git。只有工作規模大到要靠這份紀錄才能信任結果時，才 commit。

## 交還前：對照對話紀錄稽核

1. **找對話紀錄。** 讀 `~/.claude/projects/<slug>/` 底下最新的 `.jsonl`。`<slug>` 是工作目錄的路徑，每個非英數字元換成 `-`（`/Users/you/proj` 變成 `-Users-you-proj`）。子代理的對話紀錄在 `<session>/subagents/`。不要在 `~/.claude/projects/*/` 之間搜尋，那會讀到無關的私人對話。
2. **範圍。** 只查這次執行寫的列：從這次執行的 `start` 列（或這次建立紀錄時的第一列）到另一次執行的下一個 `start` 列為止。
3. **檢查。** 每一列都對應真實的決定或動作；每一列的證據都找得到，且顯示該列宣稱的內容；塑造了工作卻沒記下的分岔、轉向或放棄的做法是缺口，補上。
4. **改紀錄，不改說法。** 稽核不編輯、不移除任何一列，即使是捏造的。某列不是真實的決定或動作，或主張或證據有誤，新增一列取代它，寫實際發生的事與找得到的指標。這次執行自己的工作顯示範圍外某列有誤時，同樣新增一列取代。

## 交還前：第三方審查

派一個沒參與這次工作的子代理，模型依入口檔的「模型」一節，用 `judgment` 角色，盡量用與做這項工作不同的模型。做不到時，在回報說明。自我審查不能取代這一步。它讀紀錄與這次執行的對話紀錄，不重做工作，只標出使用者該注意的地方：

- 證據薄弱或缺漏的決定。
- 被跳過的驗證，或對話紀錄裡沒有證明就宣稱做過的驗證。
- 事後看來有風險的選擇：過早、範圍擴大、只掩蓋症狀。
- 使用者快速瀏覽時會漏掉的缺口。

## 回報

有產出紀錄的執行，每則回覆以「需要注意」結尾：第一行寫審查者用的模型，接著列出每個標記，各指向具體的列或時刻。「沒有標記」是有效的內容，只寫模型名稱不算。

要在終端機看紀錄，用 `column -s$'\t' -t decisions.tsv`。由上往下讀，順著證據指標抽查。
