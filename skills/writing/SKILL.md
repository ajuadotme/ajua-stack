# Writing

給人讀的文字照這份規範寫。修改既有文字時，只改違反規範的地方，不改意思。

## 動筆前

- **讀者是誰，讀完要做什麼。** 一句話說不出來，就還沒想清楚。
- **結論放最前面。** 讀者只看第一段也要能行動。
- **只留讀者用得到的。** 過程、試過的路、花的力氣都不寫，除非讀者需要它才能判斷。

## 句子

- 短句。一句只講一件事。
- 主詞明確。誰做了什麼，寫出來。
- 用具體的名詞與數字。「快很多」改成「從 2.1 秒降到 0.4 秒」。
- 一個概念只用一個名稱，全文一致。
- 專有名詞保留原文，首次出現時用一句話解釋。
- 優先用肯定句。「不要不檢查」改成「要檢查」。
- 不確定就說不確定，並說明原因。已確認的事不用「可能」「或許」「大致上」。

## 不寫

- 開場白與收尾語：「以下是」「希望對你有幫助」「總而言之」「綜上所述」。
- 空泛的強調：「值得注意的是」「非常重要」「關鍵在於」「不僅如此」。
- 預告：「接下來我會說明」。直接說明。
- 自問自答：「為什麼？因為」。
- 「不是 X，而是 Y」，除非真的有人以為是 X。
- 三個一組的排比，除非剛好就是三件事。
- 比喻，除非它比直接說明更短、更準。
- 長破折號。改用句號或逗號。
- 堆疊的形容詞與副詞：「強大而靈活的」「順暢地」。

## 排版

- 台灣用語：程式、檔案、資料、預設、設定、資料夾。
- 中文與英文、數字之間加一個半形空格。
- 中文用全形標點。程式碼、指令、路徑用反引號。
- 可以比較的內容用表格。有順序的用編號清單。並列的用項目符號。只有一兩項就寫成句子。
- 標題寫內容，不寫類別。「安裝」比「安裝說明」好。「為什麼會慢」比「背景」好。

## 文件類型

動筆前分清楚是哪一種，不要混在一起。

| 類型 | 讀者要的 | 寫法 |
|---|---|---|
| 教學 | 第一次做成一件事 | 一步一步帶，每步都有看得到的結果 |
| 操作指南 | 完成一項具體工作 | 只寫步驟與必要條件 |
| 參考 | 查一個事實 | 完整、一致、好查 |
| 說明 | 理解原因 | 講背景、取捨與理由 |

## commit 訊息

- 第一行 50 字以內，寫改了什麼。
- 空一行後寫為什麼改。怎麼改已經在程式碼裡，不重複。
- 一個 commit 只做一件事。

## 完成前

逐句讀一次。每一句問：刪掉它，讀者會少知道什麼？答不出來就刪。
