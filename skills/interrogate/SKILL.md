# Interrogate

多個審查者設法弄壞一份改動或一個設計。只留下實際執行證實的發現。回報發現，不套用修正。

## 界定

1. **範圍。** 使用者指定時照指定。沒指定時，是工作目錄裡尚未 commit 的改動。沒有未 commit 的改動，就取最近一個 commit。
2. **意圖。** 根據使用者的訊息與 commit 訊息，用自己的話寫出這份改動要達成什麼。意圖不清楚時問使用者。

## 分派

1. **審查者。** 模型依入口檔的「模型」一節，用 `panel` 角色，一個項目派一個子代理，`subagent_type: "general-purpose"`。某個模型被拒絕時，換一個可用的或拿掉該席位，至少保留兩個審查者，並在回報說明。
2. **隔離。** 每個審查者用 `isolation: "worktree"`。把範圍內尚未 commit 的改動複製到每個 worktree。
3. **同時啟動。** 在同一則訊息裡啟動全部審查者。每個都給範圍、意圖，以及下面這份交辦：

> 弄壞這份改動。每個發現都要對真實的程式碼實際執行來證實，例如一個失敗的測試、一支重現腳本，或顯示錯誤行為的指令輸出。審查的是設計或計畫時，跑一個原型，或探測目前的程式碼。重現用的東西放在你自己的 worktree。每個發現回報標題、確切的指令、它印出的輸出，以及依意圖應該得到的輸出。沒有實際執行過的不寫，包括風格、命名、結構，以及要等未來某個改動才會出事的風險。沒有發現也是有效的結果。

4. **退出。** 某個審查者沒有產出，就用剩下的繼續，並記下這次退出。

## 驗證

1. **重跑。** 自己重新執行每個發現的指令。輸出確實顯示失敗，且這個失敗違反意圖，才保留。其餘捨棄。
2. **合併。** 根本原因相同的發現合成一個。
3. **全部保留。** 不同審查者會找到不同的失敗。不挑某一個審查者的清單，保留每一個驗證過的發現。
4. **收尾。** 移除所有 worktree。要保留的成果先併回目前的 branch。

## 回報

- **意圖：** 你寫出的意圖。
- **發現：** 每個驗證過的發現，寫指令、輸出、它怎麼違反意圖、哪個審查者找到。一個都沒留下時，寫「沒有驗證過的發現」。
- **捨棄：** 每個審查者被捨棄的發現數與原因。
