# Catch up

讓使用者跟上進度。假設使用者記得自己在這次指令之前的最後一則訊息，之後的都不記得。本輪只讀：不改程式，不啟動任何東西。

## 蒐集

- 自那則訊息以來你做的事，以及子代理的回報。
- 等使用者處理的事：只有使用者能做的決定或步驟，例如產品選擇、核准、不可復原的動作。你自己還能做的不算。不為了湊內容而編造決定。
- 每個要呈現的數字，對照來源再確認一次。

## 回覆

1. 一句話開頭：有什麼在等使用者，或沒有。
2. 發生了什麼：使用者要求的每件事一行，寫結果，以及已完成、進行中、失敗或未檢查。順手修掉的問題也寫。有截圖就放截圖。
3. 等使用者決定的事：每一項寫決定是什麼、你的建議、對使用者的影響、依據、風險。在選項之間選擇時，列出每個選項的好處與代價。
4. 一行寫你還能繼續做的工作。

白話，短句。講對使用者而言什麼變了，不講你怎麼做的。不放 hash、路徑、指令，除非使用者需要它才能行動。什麼都沒發生也沒有事在等，就這樣說，然後停。
