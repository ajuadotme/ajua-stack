# 試做比較

產出是「決定」，不是程式。試做品用完就丟，正式版本之後走 `feature.md`。

本流程不追求最小改動與程式品質。求快，把嚴謹用在選對方向。可以提出使用者沒要求的變化。

1. **講清楚要回答哪個決定。** 哪種版面、哪種互動、哪種做法、哪個較快。說不出來就不試做，改走 `feature.md`。
2. **方向開放時先找參考。** 整理幾個方向讓使用者挑，挑定後才動手做。方向已定就略過。
3. **在系統暫存目錄的獨立資料夾做。** 不放進專案，不 commit。畫面的決定用最輕的方式做出來。行為或速度的決定寫最小的腳本。不寫測試，不做抽象。
4. **多個方案放在一起比。** 同一個頁面用按鈕切換，各自標上名稱。
5. **實際觀察。** 畫面：每個方案截圖並操作一次。行為或速度：印出結果或量時間。
6. **提出方案、取捨與建議。**

**回報：** 試了哪些方案、截圖或觀察到的輸出、取捨、建議、試做品的位置。明講試做品要丟。
