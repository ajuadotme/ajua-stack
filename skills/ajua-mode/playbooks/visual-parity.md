# 畫面比對

基準就是規格，不能碰。一致與否以影像 diff 驗證，不用眼睛看。

1. **先建基準。** 遷移前建立視覺回歸 harness，擷取目前元件各種狀態的截圖。比對兩套實作時，也擷取目標的截圖。沒有基準就不能宣稱一致。這是阻擋性的前置條件，不是後續待辦。
2. **把防走捷徑條款寫進交辦並堅守。** 不改 harness，不竄改基準，不為了讓 diff 通過而重構元件。基準看起來不對時，停下來問，不改它。
3. **一次遷移一個元件。** 共用的基礎元件先遷移，作為阻擋性的階段。其餘元件平行進行，每個元件一個子代理，各用一個 worktree，依入口檔的「存檔」一節。
4. **逐元件比對到 diff 為零。** 以影像 diff 比對每個元件與它的基準。diff 不為零就是失敗，調查像素差異。每個元件都用 `/loop` 反覆比對，直到 diff 為零。
5. **存檔。** 每個元件或每個安全的批次一個 commit，依入口檔的「存檔」一節。

**回報：** 已遷移的元件、每個元件的 diff 結果、基準 harness 的位置、還剩什麼。
