# 整理

結構改變，行為不變。途中發現缺功能或真正的問題，記下來並在回報列出，不在本次處理。想做的是重新設計，就明講並改走 `feature.md`。

1. **先釘住現有行為。** 寫一個測試、快照，或新舊輸出比對腳本，記錄目前的行為，然後才動結構。型別檢查與 lint 不算。
2. **說出目標形狀。** 如果今天重寫：檔案怎麼分、資料長怎樣、誰呼叫誰。形狀已經清楚的程式不動。結果必須是分支或不合法的狀態變少，不是多一層包裝。
3. **先減後加。** 先刪掉沒用的程式、只有一個呼叫者的包裝、多餘的檢查，再引入新形狀。
4. **小步移動。** 每一步之後，第 1 步的檢查都要通過。改介面時，一次改完所有呼叫處並刪掉舊的，不留相容層。每次改名都對照實際檔案抽查，字串與文件裡的名字容易漏。
5. **在真正的成品上證明行為沒變。** 較大的整理要跑新舊輸出比對。
6. **確認值得留下。** 標準是更容易讀懂。說不出哪裡變好，就退回。
7. **存檔。** 分成小而有序的 commit：先刪除，再重整。

**回報：** 結構改了什麼、用什麼釘住行為、行為沒變的證據、哪裡更好讀、哪些留下與退回。
