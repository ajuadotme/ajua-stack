# 執行期診斷

對執行中的程序加觀測埋點取得證據，不從原始碼推論。交付的是附引證的診斷，不是修正。

1. **擷取即時訊號。** 在問題發生的同一個地方操作。空轉的程序抓 CPU profile，記憶體洩漏抓 heap snapshot，畫面異常抓 CDP 追蹤紀錄。要真實的產出物，不要猜。
2. **縮減到關鍵證據。** 熱路徑上的函式、從洩漏物件到 GC root 的 retainer 鏈、沒有輸入卻在觸發的迴圈。大型產出物交給子代理解析，主對話只留縮減後的發現。
3. **先證明機制再相信。** 在執行中的程序上用 CDP eval 注入觀測埋點，或不重新載入、直接 hotfix 正在跑的程式碼，以低成本確認假設。注入與 hotfix 只能對自己啟動的實例做。使用者正在用的那一份只做唯讀觀測，要改動先問。
4. **對回原始碼。** 寫出檔案、symbol，以及負責配置或排程的那一行。
5. **交回診斷。** 不改檔案，略過入口檔的「存檔」一節。使用者沒要求就不修。找到原因後改走 `fix-bug.md` 或 `perf.md`。

**回報：** 擷取到的訊號、縮減後的發現、如何證明機制、原始碼位置、產出物路徑。
