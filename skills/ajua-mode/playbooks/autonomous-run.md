# 長時間自主執行

先定義完成，再一路做到完成，中途不停。完成條件必須是能執行的檢查。卡住時換方法，絕不放寬完成條件。

1. **先定完成條件。** 第一輪之前，把完成條件寫成能執行的檢查，例如測試全部通過、重現的問題不再發生、像素差異為零。
2. **選喚醒方式。** 有背景工作可等，例如建置或測試跑完、某個 branch 有新的 commit，就等它的完成通知。否則用 Claude Code 的 `/loop` 指令定時檢查，間隔寫進紀錄。需要監看時派子代理，模型依入口檔的「模型」一節，角色 `routine`。
3. **每一輪只做最小改動。** 做證據支持的最小改動，對照完成條件驗證，有進展就 commit，沒幫助的丟掉。丟掉時只還原自己的改動，不用 `git reset --hard`。「可能有幫助」的保險改動要還原，不順便留下。
4. **途中的問題自己處理。** 途中發現對目標有幫助的事，例如壞掉的技能、相關的 bug、不穩定的驗證、工具故障、沒人接手的後續、可修正的偏移，照 ajua-mode 對應的流程表自己處理。目標以外的修正分開 commit。不把可復原的工作留給使用者，不用 `AskUserQuestion`。處理完回到完成條件。
5. **只有三種事提給使用者，其餘照常推進。** 入口檔「先問」清單上的事、任何實驗都無法決定的產品或偏好判斷、真正的死路。需要等使用者決定時，只停那一項。
6. **每輪留紀錄。** 讀 `${CLAUDE_PLUGIN_ROOT}/skills/worklog/SKILL.md` 並照做，每輪一列：改了什麼、完成條件有沒有前進。
7. **完成條件成立才停。** 停滯不是停下來的理由，換做法突破。遇到真正的死路就回報，不原地打轉。

**回報：** 完成條件、跑了幾輪、commit 了什麼、丟棄了什麼、完成條件的最終狀態。
