# 加功能

用於新功能，或改變現有行為。

1. **讀懂受影響的部分。** 它現在怎麼運作，誰在用它。
2. **先定形狀。** 資料的結構，以及對外怎麼被使用。有多種合理做法且選錯代價高時，先走 `prototype.md`。
3. **切成小單元。** 寫下四項，不適用的也保留並註明原因：
   - 哪一步必須先完成。
   - 哪些部分互不相干，可以各自進行。
   - 哪些會動到同一個檔案或同一份資料。這些要排隊。
   - 最小的安全切法。
4. **實作。** 一次一個單元：做、驗、commit。範圍大時交給子代理（角色 `build`），交辦寫明檔案範圍、資料形狀、完成條件。
5. **在使用者實際使用的地方驗證整個功能。** 結果不明確，或在別的地方驗的，不算通過，在回報裡標出。

**回報：** 做了什麼、選了哪個做法與原因、第 3 步的四項、驗證方式與證據、尚未決定的事。比較過不同做法時，用表格列出。
