# 接手工作

接續先前中斷的工作。先前留下的紀錄是權威輸入：讀它，不重做。

1. **找到先前的紀錄。** 依序找：專案的 `.claude/resume.md` 接續紀錄、`git log` 裡的 `wip:` commit 與 `worklog` 技能留下的紀錄、本機對話紀錄。對話紀錄在 `~/.claude/projects/<slug>/<session>.jsonl`，slug 是目前專案的路徑，把每個非英數字元換成 `-`；子代理的紀錄在 `<session>/subagents/`。不對 `~/.claude/projects/*/` 做 glob，那會讀到其他專案的私人對話。先讀概要與最後幾則訊息，再往回找決定點。長的對話紀錄交給子代理解析，主對話只留精簡的時間線。模型依入口檔的「模型」一節，角色 `routine`。
2. **重建狀態。** branch 與 worktree（`git worktree list`）、已完成的 commit（`git log`，以及對開工前的 commit 做 `git diff`）、未完成的任務、已做的決定、停掉的子代理。不重新推導一遍。
3. **確認現況與紀錄相符。** branch、最後一個 commit、工作樹狀態（忽略 `.claude/resume.md` 本身）、各 worktree 都要對得上接續紀錄的「目前狀態」。`wip:` commit 內文寫明壞掉的地方，記下來。對不上就先查清楚差異，再往下。
4. **比對已完成與待完成。** 把已完成的和原本的計畫對照，說出接續點。不重跑先前的重現，不重做已完成的工作。想「從頭驗證一次」，代表你把權威紀錄當成不可信。
5. **對照原始目標驗證承接的說法。** 在實際成品上驗證。先前的自我回報不算證據。
6. **轉到對應的流程表。** 選定結論：繼續執行、交付已完成的建議、確認或推翻先前的結論，或對失敗的執行做事後檢討（讀 `${CLAUDE_PLUGIN_ROOT}/skills/reflect/SKILL.md` 並照做）。接手完成後，刪除 `.claude/resume.md`，它是 `pause.md` 建立的檔案。本流程到此為止，其餘由轉過去的流程表負責。

**回報：** 先前停在哪、承接了什麼、重做了什麼（最好沒有）、接續點、結果。
