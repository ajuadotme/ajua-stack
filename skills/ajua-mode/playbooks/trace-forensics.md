# 紀錄檔診斷

從已擷取的產出物做出診斷。產出物是固定的資料集，讀它，不重跑。要對執行中的程序加觀測埋點，改走 `runtime-forensics.md`。

1. **辨識格式並載入。** 用通用工具：cpuprofile 與 `.json.gz` 用 DevTools 或追蹤紀錄解析器，spindump 用文字編輯器，heapsnapshot 用 heap 工具。大型產出物交給子代理解析，主對話只留縮減後的發現。
2. **轉成可查詢的形式。** 把追蹤紀錄或 heap snapshot 倒進放在系統暫存目錄的 sqlite，每個 sample、frame 或 node 一列。先有可查詢的形狀，再開始讀。
3. **縮小到原因。** 查佔用最多時間的 frame，沿呼叫樹走到熱路徑。記憶體洩漏時，沿著從洩漏物件到 GC root 的 retainer 鏈走。spindump 時，找出卡在 CPU 上或被阻塞的執行緒，以及它的等待原因。
4. **歸因到原始碼。** 用產出物本身的 symbol，把熱點 frame 對應到檔案、symbol 與行號。沒有原始碼對應的 frame 還不算診斷：把 symbol 解析出來，或明說產出物沒帶 symbol。
5. **確認。** 有成對的擷取時，diff 前後兩份產出物來確認。沒有時，把發現標為產出物能支持的最強假設，不是已確認的原因。
6. **交回診斷。** 不改檔案，略過入口檔的「存檔」一節。使用者沒要求就不修。找到原因後改走 `fix-bug.md` 或 `perf.md`。

**回報：** 產出物與格式、縮減後的發現、原始碼位置、產出物路徑、是否有成對的擷取確認。
