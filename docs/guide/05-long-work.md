# 大型與長時間的工作

這章處理做不完一輪的工作：要拆階段、要中斷、要讓 Claude 長時間自己跑，或要多個子代理一起做。

## 多階段計畫

大工程先拆階段，你同意計畫後才動手：

```
/ajua-stack:ajua-mode 把整個專案的樣式系統遷移到新版。拆成小階段，每階段都有驗證方式，先給我看計畫。
```

計畫寫到 `docs/plans/<名稱>.md`，你同意才會執行。要求結果與原本完全一致時，把標準寫進指令。

## 安全暫停與接手

要關機、離線或換對話時：

```
/ajua-stack:ajua-mode 我要離開了，把目前的工作安全暫停。
```

它會把進行中的步驟做完或退回，停掉子代理，把你的未存檔改動做成一個 `wip:` commit，並寫接續筆記到 `.claude/resume.md`。這個檔案不進版本紀錄，接手完成後會刪除。之後在新對話接續：

```
/ajua-stack:ajua-mode 接手上次中斷的工作，先確認哪些做完了，再從那裡繼續。
```

說「繼續做」不會觸發暫停。

## 長時間自主執行

要 Claude 不停下來，做到完成條件達成為止。先確認四個前提：

1. 你自己做過一次，或看過 Claude 做一次，知道好的結果長什麼樣子。
2. Claude 有你自己會用的工具與訊號，例如驗證技能、profiler、log。
3. 每個階段都能證明自己的成果，做不到標準時能喊停。
4. 你已經讀過幾次對話，把重複出現的失敗變成檢查。

四點都成立，才放手讓它跑。有任何一點不成立，就在旁邊看著跑。

交接要寫目標、完成條件與逃生出口：

```
/ajua-stack:ajua-mode 我要去睡了。把所有呼叫端遷移到新的 parser，完成條件是舊的呼叫端歸零、所有測試通過。每個決定都記錄下來。真的卡死就停下來寫明原因。
```

途中遇到相關的問題，它會自己處理並分開 commit。它只為不可復原的動作、產品方向與真正的死路停下來。時間長度不是完成條件。「做四小時」沒有東西可以檢查，要給能通過或失敗的判斷。

## worklog：事後檢查決定

`worklog` 把每個決定記成一份可事後檢查的紀錄：做了什麼、為什麼、證據、結果。

```
/ajua-stack:worklog 記錄這次遷移的每個決定。
```

紀錄是工作目錄的 `decisions.tsv`，預設不 commit。交還前會派另一個子代理審查，回報結尾列「需要注意」。回來後先讀紀錄，稽核決定，不用重看整段過程。

## arena 與 swarm

兩者都派多個子代理，花費較高。

`arena` 讓多個子代理各做一版，再取各版的長處。版本數由 `panel` 清單決定，不足兩個會停下來告訴你。用在做法未定、事後很難改的決定：

```
/ajua-stack:arena 設計快取鍵的格式，做三個版本。這個格式之後很難改。
```
`swarm` 讓多個子代理分頭處理不同部分，彙整成一份報告。用在需要涵蓋範圍的工作：

```
/ajua-stack:swarm 檢查 packages 底下每個套件的測試，一個套件一個子代理，彙整成一份報告。
```

要涵蓋不同部分用 `swarm`，要比較同一件事的不同做法用 `arena`。

`arena` 的執行者、`interrogate` 的審查者，以及會改檔案的 `swarm` 工作者都會用 worktree，結束後自動收掉。

## 清理 worktree

用完的 worktree 與 branch 會占磁碟：

```
/ajua-stack:ajua-mode 清掉用完的 worktree 與 branch。
```

它會先問你哪些 worktree 或對話還在用，再依合併狀態與未 commit 的內容分類，只刪證據確認安全的。未 commit 的內容與尚未併入的 branch 都要你確認才刪。
