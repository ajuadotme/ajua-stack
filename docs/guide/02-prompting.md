# 怎麼下指令

指令寫得準，Claude 就少猜。這章說明該寫什麼、不用寫什麼，以及方向偏了怎麼修。

## 該寫的四件事

每件事一句話就夠：

- **目標。** 哪裡有問題，或你要什麼。
- **完成條件。** 要能通過或失敗。「做得更好」不是條件。
- **要看的證據。** 截圖、指令輸出、前後對比的數字。
- **真正的限制。** 例如「先重現」「行為不能變」「先不要改檔案」。

四件事都有的例子：

```
/ajua-stack:ajua-mode 載入商品列表要等 6 秒。先量測再找原因。完成條件是同一份資料降到 2 秒內，給我看修改前後的數字。
```

寫得更短也行。目標加一個可檢查的結果，就足夠讓流程表運作：

```
/ajua-stack:ajua-mode 點儲存之後畫面跑版。修好後截圖給我看。
```

## 不用寫的事

- **流程表的名字。** 描述任務，`ajua-mode` 會自己選。
- **做法。** 說要達成什麼，讓 Claude 找最合適的路。
- **技能清單。** 不要寫「先用 arena，再用 interrogate」。流程表已經排好順序，手寫的順序容易漏步驟。
- **你對原因的猜測。** 猜測會讓搜尋縮到你指的地方。先說症狀，讓 Claude 自己找。

## 一件事一個任務

一則訊息有多件工作時，`ajua-mode` 會依序處理，前一件驗證通過才做下一件。換主題時明說：

```
/ajua-stack:ajua-mode 換一個任務。查一下為什麼登出後快取還在，先不要改任何檔案。
```

## 提示不確定時：sharpen

送出前想先確認提示夠不夠到位，用 `sharpen`。它只改寫你的提示，不動手做：

```
/ajua-stack:sharpen 新增一個深色模式的設定選項。
```

讀完改寫版，再自己決定要不要送出。

## 用一句話修正方向

做到一半發現方向偏了，不用重寫整個指令。直接說哪裡不對：

```
我說的是先重現，還沒有要你修。
```

```
我要看實際輸出，不是 build 通過的訊息。
```

```
只改按鈕的邏輯，不要動其他頁面。
```

```
這個做法太大了，用最小的改動。
```

方向偏得很遠，就回到最近一次你滿意的狀態，重新說明目標與限制。
