# 讓外掛越用越合你

預設流程適用大多數情況。用久了，你會發現自己的習慣與常見的錯誤。這章讓外掛把它們記下來。

從小處開始。直接下指令，同一個失敗出現第二次，再加一項檢查或技能。

## reflect：整理教訓

做完一件讓你學到東西的任務後：

```
/ajua-stack:reflect 這次花太久了，整理我們學到的，讓下次不會重蹈覆轍。
```

`reflect` 讀對話，只留下會改變未來做法的教訓，整理成技能的修改提案。你核准後才會動技能。它不改外掛本身：教訓屬於專案或個人技能時，改那裡的檔案；屬於外掛本身時，由你決定要不要改外掛的原稿。只有一次的怪事不是規則，不要核准。

## correct：把重複的錯誤變成檢查

同一個錯誤你糾正第二次，就該修環境，不是修下一個提示。`correct` 會改用最穩固的方式擋住它：

```
/ajua-stack:correct Claude 一直直接呼叫資料庫，沒有經過 repository 層。
```

優先順序是：讓錯誤不可能發生的結構、型別或 lint、測試、文件。文件最弱，Claude 略過時不會有任何東西失敗。它會證明新的檢查能在真實發生過的錯誤上失敗。它會直接改專案的程式，每個錯誤類別一個 commit。

## automate-me：做成你自己的技能

```
/ajua-stack:automate-me
```

它從過去的對話歸納你的工作風格，包含偏好的回覆方式、驗證習慣與流程，再問你哪些才是真的，最後做成 `<代號>-mode` 技能，放在 `.claude/skills/` 或 `~/.claude/skills/`。過程會派多個子代理讀對話紀錄。習慣改變了就再跑一次，只會更新有新證據的部分。

## 撰寫技能

已經知道要固化某個工作流程時，描述任務即可，`ajua-mode` 會選「撰寫技能」流程表：

```
/ajua-stack:ajua-mode 寫一個技能，用來檢查資料庫 migration 是否安全。
```

給 Claude 讀的文字，標準比給人讀的更高。一句沒有用的話，會變成之後每次照做的指示。用流程表，不要自己隨手寫。

## setup：設定模型

外掛依角色指派子代理的模型：

- `build`：實作與除錯。
- `judgment`：判斷與文字。
- `routine`：機械式修改與驗證。
- `panel`：審查與比稿的小組。

```
/ajua-stack:setup
```

它先偵測可用的模型，問你要 large、medium 或 small 預算（決定推理等級），列出四個角色的設定讓你接受或改其中一個，再寫進 `~/.claude/rules/ajua-stack-models.md`，下一個對話才生效。重跑時以現有的值為起點，不會蓋掉你手動改過的設定。想少花 token，選 small，或把 `build` 與 `routine` 換成較便宜的模型，並縮短 `panel` 的名單。每個項目會派一個子代理，至少要兩個。
