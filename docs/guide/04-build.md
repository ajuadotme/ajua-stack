# 做東西

這章列出每種常見的工作怎麼下指令，以及完成後怎麼檢查。流程表由 `ajua-mode` 自己選，你不用指定。

## 試做比較

做法未定時，先做幾個版本再比較，不要爭論：

```
/ajua-stack:ajua-mode 設定頁的篩選器先做兩三個版本，放在同一個切換器後面，截圖給我比較。
```

方向還開放時，它會先整理幾個方向讓你挑，挑定才動手。試做品放在系統暫存資料夾，不在專案裡，用完即丟。

## 加功能

說出行為，以及什麼不能變：

```
/ajua-stack:ajua-mode 新增一個設定選項，讓使用者能關閉通知音效。其他設定的行為不能變，兩種狀態都要實際操作給我看。
```

## 修問題

說出症狀，並要求先重現。它會追到根本原因再修，不是蓋掉症狀：

```
/ajua-stack:ajua-mode 按下再玩一次的按鈕沒反應。先重現，再修，修好後按一次截圖給我。
```

## 整理

整理只改結構，行為不變。要先記下現在的行為，改完再證明沒變：

```
/ajua-stack:ajua-mode 把日期處理的函式集中到同一個模組，行為不能變。先記錄目前的輸出，改完比對。
```

## 效能調校

給量測，不是印象。它會量測、找瓶頸、改善、再量測：

```
/ajua-stack:ajua-mode 商品列表載入要 6 秒，找出慢在哪裡，修掉後給我看前後的數字。
```

要針對單一指標反覆改進，說出指標與目標。診斷執行中的記憶體洩漏或閒置時耗用 CPU，或讀已擷取的效能紀錄檔，也是描述症狀即可，但這幾種只交診斷，不修，要修請另外說。指標爬升會在專案留下 `experiments.tsv`（不進版本紀錄），也會建量測用的 harness。

## 畫面比對

畫面改版或重寫時，讓新畫面與原本的畫面逐一比對到一致。它會先替原本的畫面建截圖基準，再用影像 diff 比到零。多個元件會平行派子代理，基準看起來不對時會停下來問你：

```
/ajua-stack:ajua-mode 把設定頁從舊元件換成新元件，畫面要跟原本完全一樣，附上比對結果。
```

## 完成後的檢查

做完的東西，換一雙眼睛再檢查一次。

`interrogate` 派多個子代理試著找出毛病，只留下實際重跑證實的，並說明每個審查者捨棄了幾項、為什麼。沒指定範圍時，查尚未 commit 的改動，沒有的話查最近一個 commit。你可以推翻它的判斷。會花較多 token：

```
/ajua-stack:interrogate 這次改動的整個 branch，只報真正的 bug 或退化，不要吹毛求疵。
```

`comments` 刪掉不必要的註解，註解背後的 workaround 與限制也會在範圍內改成程式碼（型別、檢查或測試），加檢查前會問你。沒指定範圍時，處理尚未 commit 的改動，沒有的話取最近一個 commit：

```
/ajua-stack:comments 這次改動的檔案
```

`writing` 是中文技術寫作規範，用於回覆、文件與 commit 訊息：

```
/ajua-stack:writing 檢查 README 的修改。
```

`typescript` 是 TypeScript 寫法規範。碰到 `.ts` 或 `.tsx` 檔案時用：

```
/ajua-stack:typescript 檢查這次新增的型別。
```

小改動不需要全跑。改動大、不放心或要交給別人看時才用。
